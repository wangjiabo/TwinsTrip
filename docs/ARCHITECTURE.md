## 2. 模块职责

### 2.1 前端 — 微信小程序

| 模块 | 职责 | 技术 |
|------|------|------|
| 页面层 | 6 个主要页面（首页、行程、清单、应急、地图、宝宝档案）| 原生 WXML/WXSS + TypeScript |
| 状态管理 | 全局状态（双娃状态、当前行程）| MobX 或 Zustand |
| 地图组件 | 腾讯地图小程序 SDK | 腾讯地图 SDK |
| 本地缓存 | 离线可用的数据（清单、上次行程）| wx.setStorageSync |
| 实时同步 | 与后端 WebSocket 连接，接收行程变更 | Socket.io-client |

### 2.2 后端 API

| 模块 | 职责 | 技术 |
|------|------|------|
| 行程引擎 | 作息模板、时间冲突检测、延误重排算法 | Express + TypeScript |
| 物资计算 | 双胞胎数量计算、冗余系数、场景模板 | 纯数学计算 + 模板匹配 |
| 应急决策 | 最近资源点查找、行程降级建议 | 腾讯地图 API + 规则引擎 |
| 实时协作 | 双终端状态同步 | Socket.io + Redis Pub/Sub |
| 用户认证 | 微信登录 (openid) | Passport.js |

### 2.3 外部服务

| 服务 | 用途 | 选择理由 |
|------|------|---------|
| 腾讯地图 | POI 搜索、路线规划、逆地理编码 | 微信小程序原生支持，无鉴权问题 |
| Open-Meteo | 天气预报 | 免费、无 API Key、精度足够 |
| 高德地图 (备选) | POI 补充 | 母婴室等 POI 数据可能更全 |

## 3. 关键算法

### 3.1 延误自动重排

```
输入: 原行程序列 T = [t1, t2, ..., tn], 延误时长 delay
输出: 新行程序列 T'

算法:
1. 找到延误起点 ti（喂奶/nap 时间延长导致的延误）
2. 从 ti 开始，所有后续节点的 start_time += delay
3. 检测冲突：
   - 新 start_time 是否落在宝宝 nap 窗口？
   - 新到达时间是否超过景区闭园时间？
   - 节点间间距是否合理（留 buffer）？
4. 冲突处理策略（按优先级）：
   a) 缩短当前节点停留时间
   b) 删除非核心节点
   c) 建议附近替代（降级预案）
5. 返回新行程 + 变更说明
```

### 3.2 物资冗余计算

```
输入: 物品 item, 单人用量 single_qty, 宝宝数 n, 出行时长 hours
输出: 建议带量 total_qty

total_qty = single_qty × n × redundancy_factor(hours)

redundancy_factor:
  hours <= 2  → 1.1  (轻微冗余)
  2 < h <= 4  → 1.3  (中等冗余)
  4 < h <= 8  → 1.5  (充足冗余)
  hours > 8   → 1.8  (大量冗余)

特殊规则:
  - 纸尿裤: 额外 +2 片（防突发）
  - 奶粉: 按"瓶"为单位，向上取整
  - 应急药: 固定 +1 份
```

### 3.3 双娃时间差检测

```
两个宝宝的作息模板 B1 和 B2:
  B1.nap = [11:00, 12:30]  (开始时间 + 时长)
  B2.nap = [11:30, 13:00]

两者的 "都清醒窗口":
  最早 nap 开始 = min(11:00, 11:30) = 11:00
  最晚 nap 结束 = max(12:30, 13:00) = 13:00
  但 B2 在 11:00-11:30 可能犯困
  B1 在 12:30 后醒了但 B2 还在睡

  "黄金窗口" = 两个娃都清醒且不犯困:
    计算每个宝宝的清醒时间线，取交集
```

## 4. 部署架构

```
生产环境:

Vercel (后端 API + Serverless Functions)
├── /api/*  (REST endpoints)
├── /ws     (WebSocket)
└── Vercel Postgres (数据库)
    └── Redis (缓存层)

微信平台
└── 小程序托管 (体验版/正式版)
```

**为什么选 Vercel？**
- 免费额度足够 MVP 使用
- Serverless Functions 自动扩缩
- PostgreSQL 和 Redis 开箱即用
- GitHub 自动部署

## 5. 安全设计

| 关注点 | 方案 |
|--------|------|
| 用户认证 | 微信小程序登录 → 换取 openid → JWT |
| 数据隔离 | 每个家庭独立数据空间，openid 关联家庭成员 |
| 地图 Key | 后端代理，小程序不暴露 Key |
| HTTPS | 强制全链路 HTTPS |
